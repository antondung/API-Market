# Internationalization (i18n)

## Overview

API Hub supports **Vietnamese (vi)** and **English (en)**. The active language is persisted in `localStorage` under the key `lang`.

Default language: **Vietnamese**.

---

## System Components

| File | Purpose |
|------|---------|
| `src/i18n/index.ts` | `useLanguage()` hook, `t()` function, `getCurrentLanguage()` |
| `src/i18n/vi.ts` | Vietnamese translation strings |
| `src/i18n/en.ts` | English translation strings |
| `src/i18n/autoTranslator.ts` | DOM-level auto-translation for dynamic/injected content |
| `src/components/ui/LanguageSwitcher.tsx` | UI toggle component (dropdown variant) |

---

## Usage in Components

```tsx
import { useLanguage } from '../../i18n';

const { t, language, setLanguage } = useLanguage();

// Translate a string key:
<h1>{t('Admin Governance')}</h1>

// Language toggle:
setLanguage('en');
setLanguage('vi');
```

---

## Adding a New String

1. Open `src/i18n/vi.ts` — add the Vietnamese translation
2. Open `src/i18n/en.ts` — add the English translation
3. Use `t('your-key')` in the component

The key is the **English string** (used as fallback if translation is missing).

### Example

```ts
// vi.ts
export const vi = {
  ...existingKeys,
  'Gateway Operations': 'Vận hành Gateway',
};

// en.ts
export const en = {
  ...existingKeys,
  'Gateway Operations': 'Gateway Operations',
};
```

## Auto-Translator

`autoTranslator.ts` runs a MutationObserver that watches the DOM and translates text nodes that contain keys from the active language dictionary. This handles dynamically rendered content that may bypass the `t()` function.

```ts
// Started in App.tsx:
const stop = startAutoTranslator(getCurrentLanguage);
// Call stop() to deactivate (on unmount)
```

## Backend Notes

If the backend serves user-facing strings (e.g., error messages, API categories), they should also be translated. Two options:

1. **Client-side**: Backend returns keys, frontend translates using `t()`
2. **Server-side**: Backend accepts `Accept-Language: vi` header and returns pre-translated strings

Option 1 is recommended for consistency with the current frontend approach.
